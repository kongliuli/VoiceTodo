# VoiceTodo 命名提案 V1

> 时间：2026-09-11
> 约束（用户指定）：**中文名取自中国古典诗词，英文名为其意译**。
> 性质：候选短名单 + 推荐，**尚未做商标与商店检索**，见第 4 节。

---

## 0. 先说三个已经查实的事实

这三条决定了候选的取舍方向，不是空话。

| # | 事实 | 证据 |
|---|---|---|
| 1 | **英文里「说话 / 语音」这一族高频单词已被占满**，且多个正是「语音 → 待办」定位 | `Aloud`：macOS 应用，把口述变成 coding agent 的任务，端侧 Whisper；`Utter`：Android「voice → Notes/To-Do/Journals」，**本地存储、隐私优先**；`Scribe`：多个（App Store 语音转写、`scribe.rs` 端侧听写） |
| 2 | **英文里「待办 / 计时」这一族也被占满**，且同样有隐私向同类 | `Cue`：至少三个同名 App，其中一个正是「锁屏待办 + 专注计时 + 数据只存设备」 |
| 3 | **中文常用二字词同样拥挤** | `余音`：已被多个占用——语音交友 App、小众音乐播放器、音乐社区；且类别（社交/娱乐）与本产品冲突 |

**结论**：英文名**不要再走「Voice / Speak / Listen」这一族的单词**（何况 `VoiceTodo` 本身就要弃用），也不宜走 `Aloud / Utter / Cue` 这类已被同赛道占据的词。→ 英文走**意译词组或低频词**。

## 1. 候选短名单

| # | 中文 | 出处 | 英文意译 | 一句话定位 |
|---|---|---|---|---|

## 2. 逐项说明

### A · 知时节 / Kairos ★推荐

- **原句**：杜甫《春夜喜雨》——「**好雨知时节**，当春乃发生。随风潜入夜，润物细无声。」
- **含义**：好雨懂得时令，该来的时候自然就来；而且来得轻，不惊扰。
- **为什么最合适**：本项目调研里最致命的一类用户反感是**提醒骚扰**（Nag 停不掉、通知轰炸 → 用户干脆关通知 → 整个提醒功能作废，见 master P0-7 / 7.2）。「知时节」正好是对这件事的承诺：**在对的时候提醒你，不对的时候不出现**。一句诗就把产品原则说完了。
- **覆盖双线**：待办（该做的事在该做的时候出现）+ 计时（到点即响，不早不晚）。
- **英文意译 `Kairos`**：古希腊语，指「**恰当的时机**」，与 `Chronos`（钟表刻度上的时间）相对。一个从杜甫来、一个从古希腊来，两句话说的是同一件事——这是命名里少见的对仗。
- **记忆成本**：≈ 0（这句诗人人会背），但**不是**一个被用滥的品牌词。
- **风险**：`知时节` 可能被误读成**节气 / 时令 / 农历**类应用。缓解：图标与商店副标题必须带产品描述（如「语音待办 · 免提计时」），不裸奔。

### B · 一诺 / One Word

- **原句**：李白「一诺许他人，千金双错刀」；典出《史记·季布栾布列传》「得黄金百斤，不如得季布一诺」。
- **含义**：说出口的话就是承诺，分量比千金重。
- **为什么合适**：待办的本质就是**对自己许下的承诺**。名字自带「守信、不掉链子」的气质，与「提醒要可靠」的产品要求同向。
- **英文意译 `One Word`**：英文里「守信」的表达是 *keep one's word*，「一诺」= 一句话 = *one word*。直、短、有分量。
- **风险**：`一诺` 是常见企业名（一诺仪器等），**商标与商店重名风险高于 A**。EN 侧 `Word` 单词已被占，必须用词组 `One Word`。

### C · 偶得 / Windfall

- **原句**：陆游《文章》——「文章本天成，妙手**偶得**之。」
- **含义**：最好的东西是偶然得来的，不是硬憋出来的。
- **为什么合适**：精准描述**捕捉**这件事——念头一冒出来就得接住，否则就没了。名字本身在提醒用户「想到就说」。
- **英文意译 `Windfall`**：不期而得的收获。同为「偶然得到」。
- **风险**：偏重「捕捉」一端，对**计时 / 健身**这条线几乎没有覆盖。若产品最终主打健身，此名偏弱。

### D · 绕梁 / Linger

- **原句**：《列子·汤问》——「昔韩娥东之齐……既去而**余音绕梁欐，三日不绝**。」（成语「余音绕梁」出处）
- **含义**：声音留在屋里，三天不散。
- **为什么合适**：提醒的本质就是「**让一句话不消失**」——说完会被留在耳边，到点再响一次。
- **`余音` 已被占用，`绕梁` 取同一出处但更生僻**，占用概率低。
- **风险**：单看「绕梁」略费解，且「梁」字有建筑（房梁）联想，可能需要靠副标题托底。

### E · 私语 / Aside

- **原句**：白居易《琵琶行》——「大弦嘈嘈如急雨，小弦切切如**私语**。」
- **含义**：轻轻的、只给一个人听的话。
- **为什么合适**：一字是「**私**」（隐私），一字是「**语**」（语音）——**用两个字同时说完本产品的两条核心主张**（隐私优先 + 语音输入），且对应 D1 已拍板的「手动唤起、不像常开监听那样贴着人」。
- **英文意译 `Aside`**：戏剧术语「旁白」——只说给该听的人，场上其他人听不见。含义对得上。
- **风险**：① 有「窃窃私语」的轻微负面联想；② 容易被读成情侣/社交向（而 `余音` 已经因为撞上语音交友而排除，本名有同类风险）；③ `Aside` 作英文品牌名偏弱、也容易被理解成「在旁边」。

## 3. 推荐

**首选：A · 知时节 / Kairos**
理由：唯一一个把本产品**最脆弱的环节（提醒的时机与分寸）**写进名字的候选；出处是全国都会背的诗，记忆成本为零；中英各出自一个文明的「恰当时机」，故事讲得通；不是什么被用滥的品牌词。

**次选：B · 一诺 / One Word**
如果你更想让名字落在「**待办 / 守信**」这半边，B 比 A 更贴；代价是重名与商标风险更高。

**如果主打健身：** A 与 B 都还行，但 C（偶得）偏弱，建议届时再补一轮「健身 / 间歇」方向的诗词候选。

## 5. 改名对工程的影响（建议）

`VoiceTodo.*` 目前出现在：解决方案名 `VoiceTodo.sln`、两个工程目录与 `.csproj`、根命名空间、`%LocalAppData%/VoiceTodo/voicetodo.json` 数据路径（**涉及用户既有数据**）。

**建议**：**在 N1 检索通过、名字正式锁定之前，代码一律保持 `VoiceTodo` 不动。** 理由：改工程名与命名空间会带来大面积 diff，而当前 HEAD 连一次构建验证都还没做（master 1.3.1 标注「代码已修、待构建确认」），两件事叠在一起会让问题难以定位。

锁定后再一次性改名，届时注意两点：
1. `%LocalAppData%/VoiceTodo/` **不能直接换名**，否则老用户数据会「丢失」——需要写迁移逻辑（新目录为空则从旧目录搬）。
2. 数据文件名 `voicetodo.json` 保持稳定，只改目录。
