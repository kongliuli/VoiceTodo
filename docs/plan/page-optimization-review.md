# VoiceTodo 页面优化分析报告

> 复核日期：2026-09-11。
> 输入：`page-interaction.md`、`voicetodo-master.md`、当前 MAUI 页面与相关调用链、14 屏设计底图、Android 官方资料。
> 范围：页面信息架构、操作闭环、状态反馈、视觉与无障碍、开发优先级。本轮仅新增报告，不修改应用实现。
> 证据边界：已静态复核页面结构和关键事件，并重新目视查看清单、间歇配置、日历底图；这些是设计图，不是当前应用截图。本轮未启动 MAUI、未构建、未进行 Android/Windows 真机测试。因此不判定实际渲染通过，也不复述“已复现锁屏即丢”等未经测试的结论。

## 1. 结论

**下一阶段应让现有页面上的每个承诺都有真实结果，再处理视觉精修。** 当前 11 个 ContentPage 已提供主要页面与状态容器，但“有页面”“交互接通”“后台可靠”“设备验收通过”必须分别记录。

语音、计时、提醒确实应放在第一优先级。本次额外发现：正常新建任务的提醒没有进入系统调度、同一间歇计划从不同入口启动会改变语义、存储损坏可能被当成空库。它们直接影响页面可信度，优先于新增组件、动画和小组件。

建议保留当前浅色母版和三个主导航，不再重画整套正常态。将设计精力移到权限、保存失败、后台中断、纠错和恢复等关键状态。

## 2. 对原分析的校正

| 原表述 | 本轮复核后的表述 | 影响 |
|---|---|---|
| 11 页 / 14 屏零未实现 | 主要页面容器已有代码；14 屏中仍有多计时等能力差距，且没有本轮端到端验证 | 不将页面数量作为发布完成率 |
| 计时不落库 | 计时定义和结束时的 `TimerSession` 已有持久化；**活动计时的阶段、剩余时间与恢复信息没有可靠持久化** | 修复对象是运行恢复，不是从零再造历史表 |
| 切歌/锁屏即丢 | 页面内运行循环支持跨页面继续；进程回收会丢内存状态，锁屏和系统冻结存在未验证风险 | 分开测切 Tab、切应用、锁屏、回收与重启 |
| 固定 8 秒，每次必须等满 | 当前语音页直接采集文件，配置 60 秒上限，并支持手动结束；旧识别接口的 8 秒不能代表当前主入口 | 当前重点是真录音、正常停止与取消的区别、延迟反馈 |

| 语音纠错没有做 | 确认页已有可编辑字段；缺口是反馈、语义一致性、间歇草稿的可编辑性与保存闭环 | 保留已做成果，补齐具体断点 |
| E1/E2/E3 已修，因此构建不阻塞 | 集合订阅和可变 Title 的代码修正可见；**构建门仍待执行** | 不重新修同一个错误，也不跳过构建确认 |
| 部分 5→4 | 原对照表逐行标为“部分”的屏与汇总统计口径不一致，混入了权限和预设重复这类能力项 | 分成“屏幕覆盖表”和“能力验收表”，不要混算 |

原文“必然卸载”“所有用户第一诉求”等可作为风险表达，不应写成调研已量化证明。本轮认定它们是产品判断，没有用户留存或满意度实测数据。

## 3. 优先修复的交互断点

### P0-A：保存了任务，不等于安排了提醒

**静态事实：** `VoiceCapturePage.OnConfirmAdd`、`TextAddPage.OnConfirmAdd` 和 `TaskEditorPage.OnSaveClicked` 直接调用仓库；仓库只读写 JSON，不调通知服务。现有新页面绕开了原语音管线的提醒调度，故不能只修“删不掉通知”，还要修“新提醒根本没安排”。

**页面优化：** 保存结果必须区分“任务已保存、提醒已安排”和“任务已保存、提醒未开启/安排失败”。后者提供开启权限或重试动作，不把任务丢掉，也不要求用户重新输入。

**开发落点：** 新建、编辑时间、标记完成、删除、延后走同一套变更与调度规则；实体 ID 与系统通知 ID 的关联可持久化。UI 不各自拼一套提醒行为。

**验收：** 从语音、文字、编辑三个入口得到同一任务时，提醒时刻一致；完成/删除后停止该任务提醒；延后替换旧提醒而不是多加一条；调度失败有可恢复反馈。

证据：[语音确认](D:/FromGit/todolist/src/VoiceTodo.Maui/Pages/VoiceCapturePage.xaml.cs:508)、[文字确认](D:/FromGit/todolist/src/VoiceTodo.Maui/Pages/TextAddPage.xaml.cs:298)、[任务保存](D:/FromGit/todolist/src/VoiceTodo.Maui/Pages/TaskEditorPage.xaml.cs:250)、[仓库](D:/FromGit/todolist/src/VoiceTodo.Core/Services/TodoRepository.cs)。

### P0-B：录音界面要显示真实状态，失败后要有下一步

**静态事实：** DI 仍注册 Demo 采集；权限只有查询；语音页把文件、识别异常收敛为空文本，再显示通用失败页。

**页面优化：** 区分“等待授权 / 正在录音 / 正在整理 / 待确认 / 未听清 / 麦克风不可用 / 模型不可用”。只有采集已开始才能显示正在录音。无流式转写时不要暗示实时字幕能力；波形也应区分音量反馈和纯动效。

录音完成保留有效音频并识别；取消丢弃本次结果。两者不能只靠相同的取消令牌碰运气。失败页保留“重试”和“改用文字”，已获得的文本保留为草稿。

**验收：** 首次授权、拒绝、永久拒绝、撤销权限、无音频、识别错误均有明确路径；不重复申请已拒绝权限，不让用户停留在永久转圈页。

证据：[服务注册](D:/FromGit/todolist/src/VoiceTodo.Maui/MauiProgram.cs:56)、[识别结束处理](D:/FromGit/todolist/src/VoiceTodo.Maui/Pages/VoiceCapturePage.xaml.cs:211)、[权限状态](D:/FromGit/todolist/src/VoiceTodo.Maui/Pages/SettingsPage.xaml.cs:171)。

### P0-C：计时显示必须对应同一份计划

发现三类不同问题：

1. **轮次表示不一致。** 编辑器把多轮展开为多个 `Phase`，每段 `Rounds=1`；运行页却从首段读取总轮数。因此编辑器创建的八轮训练可能按完整阶段运行，但显示为一轮。不能仅修文字标签，要统一计划解释。
2. **最近使用丢失间歇结构。** `OnRecentStart` 只用总 `Duration` 构造普通倒计时，没有恢复 `Phases`。同一训练从最近使用重开会改变行为。
3. **后台恢复不能仅推进下一段。** 当前到期后用“现在＋下一阶段时长”重建截止时间。如果运行循环被挂起跨过多个阶段，恢复后存在整体延长的风险。需要确定暂停是否由用户发起，以及真实经过时间对应哪个阶段。

**页面优化：** 统一“第几轮 / 共几轮、当前阶段、阶段剩余、整个训练剩余”的含义；区分准备、运行、暂停、完成、系统中断。恢复失败明确显示“上次训练中断”，不能显示为正常完成。

**验收：** 语音、编辑器、最近使用启动同一计划，轮次、阶段、总时长一致；暂停只冻结当前运行；系统暂停执行后的恢复不凭空增加训练时间；结束记录保存失败有提示或待重试状态。

证据：[构建计划](D:/FromGit/todolist/src/VoiceTodo.Maui/Pages/TimerEditorPage.xaml.cs)、[最近使用与运行循环](D:/FromGit/todolist/src/VoiceTodo.Maui/Pages/TimerPage.xaml.cs:202)、[跨页计划消费](D:/FromGit/todolist/src/VoiceTodo.Maui/Pages/TimerPage.xaml.cs:645)、[内存运行快照](D:/FromGit/todolist/src/VoiceTodo.Maui/Services/RunningTimerHub.cs)。

### P0-D：存储失败不能伪装成“没有任务”

**静态事实：** 仓库加载异常直接返回空 `Store`；保存使用 `File.Create` 重写原文件。损坏或读取失败后继续写入，存在覆盖旧内容的风险；这不是已经复现的数据丢失结论。

**页面优化：** 区分空列表、加载中、读取失败。读取失败时显示重试与数据恢复入口，阻止把“空库”继续保存；保存失败保留输入，不能关闭编辑页。

**开发落点：** 保留损坏文件证据，安全写入与替换，明确错误传播。此问题优先于完整备份中心；删除撤销不能代替底层防数据损坏。

证据：[LoadAsync / SaveAsync](D:/FromGit/todolist/src/VoiceTodo.Core/Services/TodoRepository.cs:31)。

## 4. 逐页优化建议

| 页面 / 对应设计屏 | 保留 | 最应改的地方 | 可验收结果 |
|---|---|---|---|
| 今天 / 01 | 今日列表、计时摘要、底部快速记录 | 过期与今日分组；到期事项用摘要提示，避免每次回来自动打断；Debug 样例从真实库隔离 | 回首页不被连续弹页；空库是真空态；计数与列表一致 |
| 清单 / 02 | 即时筛选、搜索、行编辑 | 增加就地添加；搜索入口自动聚焦；列表/日历切换放在同一浏览上下文 | 无需回首页即可新增；返回后保留筛选和滚动位置 |
| 任务编辑 / 03 | 标题、日期、提醒、重复、备注 | 保存中防重复点击；未保存返回提示；显示无时刻时的实际默认规则；删除提供撤销 | 只保存一次；取消不变更持久数据；提醒安排与字段一致 |
| 语音聆听 / 04 | 大结束按钮、转文字 | 加权限与设备失败态；明确完成录音和退出会话的区别 | 状态与真实采集一致，用户可随时停止 |
| 识别确认 / 05 | 原话与结构化草稿 | 突出不确定时间；间歇计划提供编辑入口；长标题换行，避免关键结果被截断 | 用户不用重说整句话就能修正一项 |
| 文字添加 / 06 | 输入、防抖、解析 chips | 与语音统一时间/重复规则；用户手工修改后防止下一次解析覆盖；验证保存忙碌与错误态 | 同一句话两种入口得到同一结果；键盘不遮住保存 |
| 计时列表 / 07 | 常用计时、最近使用 | 最近使用保留原计划；运行时点新计划不得静默无反应；多计时未完成前清楚说明限制 | 运行中再次创建有明确结果，不意外替换当前训练 |
| 间歇配置 / 08 | 时长、休息、轮数、总时长 | 数字可直接输入，步进保留；休息为零应有明确定义；统一“保存并开始”行为 | 点击开始就开始，或按钮明确叫“保存并预览”，避免二次确认困惑 |
| 运行 / 09 | 大数字、阶段、下一阶段 | 增加后台可见控制、恢复/中断状态；阶段切换触觉可配置 | 锁屏/切歌后有真实状态；结束不会留下幽灵通知 |
| 暂停 / 10 | 继续、结束 | 暂停态从运行数据派生，区分用户暂停与系统中断 | 多次切页仍保持同一剩余时间和轮次 |
| 到期提醒 / 11 | 完成、延后、自定义 | 动作真正取消/替换通知；关闭含义说清；Nag 必须可终止 | 完成后该次提醒不再重复，延后只产生一次后续提醒 |
| 设置 / 12 | 分组结构 | 一级页改为用户语言；模型/路径进入高级页；声音用选择和试听；权限状态旁提供操作；持久化并回读 | 重启后设置一致；权限拒绝可恢复；读不到设置不假装保存成功 |
| 首次引导 / 13 | 示例与文字替代入口 | 不一次索要全部权限；补隐私说明入口；文案只陈述已支持的能力 | 不授权也能使用文字待办；首次录音和首次提醒分别说明用途 |
| 日历 / 14 | 月周切换、当日任务、训练记录 | 待办行接编辑；选中日期下直接添加并预填该日；待办与已发生训练记录分组 | 同一任务在日历/清单/首页都可编辑；不混淆计划和历史 |

**预设 D4 保持待定。** 可以保留首页快捷模板和编辑器模板两个入口，但应共用模板定义；不因“重复入口”擅自删除用户尚未决定的入口。

## 5. 信息架构与视觉：需要收敛的细节

### 5.1 日历归属应统一

第 14 张图把日历放在清单的视图切换里，现有实现是首页进入独立子页。建议把“清单 / 日历”定义为同一份任务数据的两种浏览方式，日期/筛选状态可保留；不强制一次重写页面结构，先增加清单可达入口与相同的行编辑行为。

### 5.2 月历不能占满小屏

当前日历上部多个 Auto 行，下面还有任务、计时历史与固定高度 240 的待安排列表。六周月份、长标题、大字体下存在剩余空间不足风险，尚未实测溢出。

建议月历可折叠成周视图；下面以一条主要滚动区域呈现当日待办和训练历史；待安排入口只保留数量与跳转，不在小屏底部再展开一个长列表。

### 5.3 触控尺寸不能由注释证明

`IconCircle` 声称“44×44 触控达标”，而母版要求至少 48dp；`CheckCircle` 实际设置 26×26，部分调用处没有独立 48dp 完成区域；计时步进按钮也是 44×44。Android 官方建议触控区域至少 48×48dp，应核对真实命中区域。[官方依据](https://support.google.com/accessibility/android/answer/7101858?hl=en)

完成圆圈的视觉尺寸可以保留，但整个完成操作要有独立足够大的命中区域，不应以整行编辑区域代替。

### 5.4 固定宽度与长文案

设置页模型选择器宽 200，左侧同时放 44 宽图标、字段名和卡片内边距，窄屏容易挤压字段名；编辑浮层统一宽 320，但没有统一可用宽度约束。改成受页面宽度约束的布局，长值独立占行或进入二级选择页。

标题可以两行；日期、重复规则和错误说明不得为保持单行而隐藏关键信息。截图适配不能替代 320/360dp、六周月份、字体放大和键盘状态检查。

### 5.5 统一图标、颜色和导航层级

- 当前多页仍混用 emoji、Unicode 箭头和普通文字图标；母版是线性图标。统一一套本地资源即可，不需要为此引入大型 UI 依赖。
- `TextMuted=#98A2B3` 不宜承载必须读懂的提示；完成项与禁用项也应有文字/图标状态，不能只有淡色。
- 只有部分子页显式隐藏 Shell 标题栏，同时页面又有自绘标题。应逐页验证是否出现重复导航或底栏干扰录音/编辑，而不是从 XAML 猜测最终渲染。
- 运行态和暂停态沿用相同布局；真实数据替换颜色与文案，不为每个状态新造一套控件。

证据：[样式](D:/FromGit/todolist/src/VoiceTodo.Maui/Resources/Styles.xaml)、[日历结构](D:/FromGit/todolist/src/VoiceTodo.Maui/Pages/CalendarPage.xaml)、[设置布局](D:/FromGit/todolist/src/VoiceTodo.Maui/Pages/SettingsPage.xaml)、[页面底图索引](D:/FromGit/todolist/docs/design/maui/screens-v1/index.md)。

## 6. 常驻语音方向：保留 D1，补齐用户控制

D1 是“用户手动开启会话，无空闲超时，手动关闭”，不等于一次按住说话，也不等于平台保证进程永远存活。当前 60 秒录音页面只是单次输入，不满足 D1 的会话生命周期。

建议用两层状态表达，不混淆：

| 层 | 用户看见的状态 | 控制 |
|---|---|---|
| 会话 | 未开启 / 已开启 / 系统中断 | 开启会话、结束会话、手动恢复 |
| 当前输入 | 等待说话 / 正在采集 / 处理中 / 待确认 / 失败 | 完成本句、取消本句、修改草稿 |

常驻会话开启时，所有主页面显示紧凑状态条，通知提供停止入口；关闭会话不应自动停止独立训练，结束训练也不应擅自关闭会话。系统杀进程或撤销权限后显示中断，不伪装为仍在聆听。

VAD 需要分析音频才能判断有人说话，它本身不意味着麦克风已关闭。界面必须区分“麦克风正在采集”和“正在执行识别”，避免以节能文案掩盖真实采集状态。

### 平台结论校正

- Android 12 的后台启动限制需要结合 target SDK，且存在官方列出的例外；Android 14 对需要 while-in-use 权限的 FGS 创建增加即时检查。默认设计采用用户可见时开启，不能笼统写成任何后台入口都绝对不允许。[后台启动限制](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start)
- 麦克风 FGS 需要相应类型声明、FGS 权限及运行时麦克风权限，并满足启动条件；它适用于麦克风采集，不应为了普通倒计时而占用麦克风。[服务类型](https://developer.android.com/develop/background-work/services/fgs/service-types)
- 本轮没有找到将“后台录音约 60 秒”定义为 Android 14 通用限制的官方依据，应从确定性规则中移除。官方明确的是后台访问限制；第三方 SDK 的观察值不能直接当平台保证。[Android 9 后台传感器限制](https://developer.android.com/about/versions/pie/android-9.0-changes-all)
- 通知权限和启动 FGS 的资格是不同概念。Android 13+ 拒绝通知权限并非简单等于“FGS 无法启动”；仍有通知创建要求和系统任务管理器展示差异。页面应按实际能力解释。[通知权限](https://developer.android.com/develop/ui/compose/notifications/notification-permission)
- 当前源码 Manifest 写 targetSdkVersion=36；最终安装包的合并 Manifest 尚未检查。若支持运行于 Android 17，还需验证后台播放、音频焦点与音量 API 的新限制，不能只测 Android 14。[Android 17 后台音频](https://developer.android.com/about/versions/17/changes/bg-audio)

计时后台承载方案和麦克风会话可以共享部分状态管理，但服务类型、权限及停止语义应分别论证，不能把四件套当作所有可靠性问题的完成证明。

## 7. 推荐推进顺序

| 批次 | 范围 | 完成门槛 |
|---|---|---|
| A：恢复可信 | 真实录音与按需权限；任务保存/调度/取消闭环；防存储损坏；隔离 Debug 样例 | 授权与拒绝都有路径；保存与提醒状态准确；不误丢数据 |
| B：训练可用 | 统一计划含义、最近使用重开、活动状态持久化与后台承载、暂停恢复、可终止通知 | 同一训练跨入口一致；锁屏/切应用/回收后的行为明确且经设备验证 |
| C：页面顺手 | 清单新增、日历编辑和当日添加、草稿保护、设置回读、统一默认时间、删除撤销 | 主要操作无需绕回首页；重启不改变用户设置 |
| D：常驻会话 | 按 D1 完成全局状态、结束入口、异常中断恢复、音频冲突处理 | 用户明确知道何时采集、何时停止；系统中断可见 |
| E：视觉与扩展 | 统一图标和命中区、长文案布局；再评估多计时、备份导出、静默时段、震动、小组件 | 核心流程通过后按真实使用频率推进 |

部分工作可并行，例如 A 的权限流程和 C 的清单新增；不要为了合并规划而让普通计时必须等到连续语音识别完成。

静默时段和每日汇总不能修复“取消失效”；回收站不能修复错误覆盖；更多模型选项不能修复没有麦克风采集。先修根因，再加体验选项。多计时是母版目标，当前如暂时只支持一个，必须明确提示而不是静默忽略。

## 8. 最小验收清单（本轮未执行）

1. **构建：** Android 与 Windows 各一次有效构建；旧 E1/E2 修正不再报错，记录真实命令与结果。
2. **首次使用：** 空库首次启动不出现样例；录音授权允许/拒绝/永久拒绝；通知拒绝后仍能保存文字任务。
3. **保存链路：** 相同标题、日期、重复和提醒分别从语音/文字/编辑进入，保存结果一致；连点不会重复创建。
4. **提醒链路：** 新建、改期、完成、删除、延后和 Nag 停止；关闭 App 后验证系统通知，不能只检查仓库。
5. **间歇：** 20秒工作＋10秒休息×8、包含末轮休息时共4分钟；编辑器/语音/最近使用三入口显示和执行一致。
6. **生命周期：** 切 Tab、切应用、锁屏、暂停后锁屏、进程回收、设备重启分别测试；记录恢复或明确中断，不混为一个 PASS。
7. **输入保护：** 保存失败保留文本；未保存返回可选择继续编辑；文件损坏不会被空库覆盖。
8. **日历：** 六周月份、跨年、重复任务日期、空日、长列表、当日添加与行编辑；训练历史按实际发生时间展示。
9. **可读可点：** 320/360/390dp，字体放大至200%，键盘弹起，读屏与外接键盘；检查独立完成区域和浮层返回焦点。
10. **设置与隐私：** 每项修改后重启回读；诊断日志不包含原始录音、完整识别文本或用户任务内容；导出前明确内容。

单元检查使用可控时间、模拟采集和模拟通知验证状态与计算；真实权限、锁屏、音频和通知通过单独的手工设备验收记录，不在单元测试里启动真实进程或 GUI。
