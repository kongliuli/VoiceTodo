### 环境坑（新增，重要）

1. **同一文件「并行」Edit 会互相覆盖**：一条消息里对同一文件发多个 Edit，后写者基于旧快照写回，先写者的改动**静默丢失**（本轮 08 的 §0 行、master 的头部行各丢过一次）→ 同文件多处修改**必须串行**，改完立刻 Grep/Read 复核。
2. **`replace_all` 会误伤历史日期**：把 `2026-09-11` 全替换为 `2026-09-14` 时，连带改了「那三节写于 2026-09-11 重构中途」这句**历史事实** → 批量替换前先 Grep 出全部出现位置，区分「本次操作日期」与「历史事件日期」。
3. **注入的 `current_time` 可能过时**：本轮 `current_time` 报 09-11，实际系统日期为 **09-14**（`Get-Date` 证实）→ 需要准确日期时以 shell/PowerShell 实测为准。
4. **删除文件**：`Remove-Item` 与 `safe-delete` 均报 `trash-failed`；**`[System.IO.File]::Delete($path)` 成功**，用 `Test-Path` 验证。
5. 本会话 bash shim 缺 `ls/head/tail/find/mkdir/cp/date` 等基础命令；`Get-Date` 等 PowerShell stdout 不回显 → 写临时文件再 Read。

### 重要教训：子代理报错 ≠ 没干活

派 `wave2-builder` 子代理时返回 `429 频率限制`（错误信息为 "Failed to execute task ... after subagent was created"）。**但它实际已经跑完并改完了全部 10 个文件 + 3 个新文件**，只是汇报环节被限流打断。
→ 教训：**子代理报错后，第一件事是 `git status` 看工作区**，判断它是否已改了文件。若已改，必须审计（读 diff + 构建验证）而不是重做 —— 重做会覆盖其成果或造成重复定义。本轮若没察觉，会把 C3/C6/C7 写两遍。

### 其他环境事实

- 全仓 `Grep`（ripgrep）在含 bin/obj/dll 的仓库上会 30s 超时 → 用 `git grep` 只扫已跟踪文件。
- `git status --porcelain | wc -l` 是判断工作区是否干净的快捷手段。
- 429 限流按账号/模型计，重置时间写在错误信息里。
